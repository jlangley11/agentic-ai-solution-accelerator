# Accelerator CLI reference

> Generated by `python scripts/generate-cli-docs.py`. Do not edit the command block manually.

The CLI emits human-readable output by default and a versioned JSON contract with `--json`. The wire schema is committed at `schemas/accelerator-cli-result.schema.json`. Install the local entry point first with `python -m pip install -e ".[dev]"`.

```text
usage: accel [-h] [--json] [--pretty] [--verbose]
             {start,status,next,review,validate,intake,discover,design,scaffold,environment,deploy,evaluate,uat,handover,operate,migrate}
             ...

Continue an Azure Agentic AI Solution Accelerator engagement without depending
on a specific coding-agent vendor.

positional arguments:
  {start,status,next,review,validate,intake,discover,design,scaffold,environment,deploy,evaluate,uat,handover,operate,migrate}
    start               inspect the repository and show the first valid action
    status              show lifecycle status and blockers
    next                show the next valid action
    review              review current repository changes
    validate            run or preview repository validation
    intake              manage the local private evidence ledger
    discover            inspect discovery readiness and required inputs
    design              validate the solution design contract
    scaffold            preview or create a scenario
    environment         inspect deployment environments
    deploy              preflight or deploy an environment
    evaluate            run deployed acceptance suites
    uat                 generate or sign UAT artifacts
    handover            generate handover artifacts
    operate             day-2 operational workflows
    migrate             initialize additive CLI state

options:
  -h, --help            show this help message and exit
  --json                emit the versioned JSON contract
  --pretty              pretty-print JSON output
  --verbose             include lifecycle detail
```

## Common workflow

```powershell
accel next
accel review
accel validate
```

Use `accel <command> --help` for command-specific options.

## Status and approval model

| Status | Exit code | Meaning |
|---|---:|---|
| `complete` / `ready` | 0 | Continue with `next_command` |
| `needs_input` | 10 | Collect only the declared missing input |
| `approval_required` | 20 | Review proposed actions before applying |
| `blocked` | 30 | Resolve the listed issue |
| `failed` | 40 | Diagnose the command failure |

Approval levels are `inspect`, `apply`, `execute`, and `destructive`. Global output flags may appear before or after a subcommand.

## Document intake and evidence disclosure

```powershell
accel intake add <path> [<path> ...]
accel intake list
accel intake review <source-id> --limit 50 --offset 0
accel intake disclose <source-id> approved_for_model --apply
```

Sources begin as `local_only`. Agent-facing commands cannot return source text or link extracted evidence to a requirement until the specific source is approved. Use `--include-text` only after approval. The private SQLite ledger is gitignored. Supported formats are MD, TXT, CSV, DOCX, text-layer PDF, PPTX, XLSX, and XLSM. The default limit is 50 MiB per source (`ACCELERATOR_MAX_SOURCE_BYTES`); macros are not executed and scanned PDFs require OCR.

## Requirements traceability

```powershell
accel intake requirement add --category <category> --statement <text> `
  --evidence <source-id>:<chunk-id> --apply
accel intake requirement decide <requirement-id> approved `
  --by <reviewer> --apply
accel intake requirement link <requirement-id> `
  --type quality_eval `
  --target evals/quality/golden_cases.jsonl#<case-id> --apply
accel intake requirement export --apply
```

Link types: `implementation`, `quality_eval`, `redteam`, `telemetry`, `ux`, and `decision`. Exported Markdown contains IDs and sanitized statements, never private source excerpts.

## Scaffold and deployment

```powershell
accel design
accel scaffold --scenario-id <id> --dry-run
accel scaffold --scenario-id <id> --apply
accel environment list
accel deploy --env <env> --region <region> --dry-run
accel deploy --env <env> --region <region> --execute
accel deploy --env <env> --region <region> --execute --apply
```

The target comes from `deploy/environments.yaml`; conflicting or unsupported overrides are rejected. Hosted apply runs both `azd provision` and `azd deploy` in the nested workspace.

## Evaluation, UAT, and handover

```powershell
accel evaluate --api-url <url>
accel evaluate --api-url <url> --execute
accel evaluate --api-url <url> --foundry --execute
accel uat report
accel uat signoff --sponsor <name> --approver <name> --apply
accel handover generate --env <env> --dry-run
accel handover generate --env <env> --apply
accel handover approve --approver <name> --apply
accel operate status
```

Foundry-native evaluation is optional and writes evaluator inputs only on the explicit `--foundry` path. A generated handover remains a draft until customer operations approval is recorded.

## MCP adapter

Install `.[mcp]` and configure an MCP stdio server whose command is `accel-mcp`. Read/preview tools are separate from apply and Azure execution tools so client permission policies remain effective.
